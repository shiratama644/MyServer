# ネットワーク構成

## 全体像

セキュリティを強化するため、**2つの仮想ネットワークブリッジ**を構成します。

- **`vmbr0` (外部ネットワーク):** 物理LANに接続。外部からアクセス可能なのは **nginx コンテナだけ**。
- **`vmbr1` (内部ネットワーク):** 外部から完全に隔離。app, db, game コンテナはここに配置。

```
              インターネット
                   │
          ┌────────▼────────┐
          │  TP-Link ルーター  │  WAN (グローバルIP)
          │  192.168.x.1     │  LAN
          └────────┬────────┘
                   │ LAN ケーブル
                   │ ポート転送: 80,443 → Proxmoxホスト
                   │
    ═══════════════╪═══════════════════════════════
         vmbr0 (外部ネットワーク)
         192.168.x.0/24
    ═══════════════╪═══════════════════════════════
                   │
         ┌─────────▼──────────┐
         │  Proxmox VE ホスト  │  192.168.x.2
         │                    │
         │  ┌──────────────┐  │
         │  │ nginx (LXC)  │  │  192.168.x.100  ← vmbr0 に接続
         │  │ :80, :443    │  │     唯一の外部窓口
         │  └──────┬───────┘  │
         │         │          │
    ─ ─ ─│─ ─ ─ ─ ─│─ ─ ─ ─ ─│─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─
         │  vmbr1 (内部ネットワーク)
         │  10.10.10.0/24
    ─ ─ ─│─ ─ ─ ─ ─│─ ─ ─ ─ ─│─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─
         │         │          │
         │  ┌──────▼───────┐  │
         │  │  app (LXC)   │  │  10.10.10.101  ← vmbr1 に接続
         │  │  :3000〜:3005│  │
         │  └──────────────┘  │
         │                    │
         │  ┌──────────────┐  │
         │  │  db (LXC)    │  │  10.10.10.102  ← vmbr1 に接続
         │  │  :5432, :6379│  │
         │  └──────────────┘  │
         │                    │
         │  ┌──────────────┐  │
         │  │  game (LXC)  │  │  10.10.10.103  ← vmbr1 に接続
         │  │  :8080       │  │
         │  └──────────────┘  │
         │                    │
    ══════════════════════════
```

## IPアドレス割り当て

### vmbr0（外部ネットワーク）

| 名前 | IPアドレス | 用途 |
|------|-----------|------|
| TP-Link ルーター | `192.168.x.1` | デフォルトゲートウェイ、DHCPサーバー |
| Proxmox VE ホスト | `192.168.x.2` | 管理画面 (https://192.168.x.2:8006) |
| nginx コンテナ | `192.168.x.100` | リバースプロキシ（唯一の外部窓口） |

> **`x` の値** はルーターの設定に合わせてください（TP-Link は `0` または `1` が一般的）。
> 帰宅後にルーター管理画面 (192.168.0.1 or 192.168.1.1) で確認。

### vmbr1（内部ネットワーク）

| 名前 | IPアドレス | 用途 |
|------|-----------|------|
| Proxmox VE ホスト (vmbr1側) | `10.10.10.1` | ゲートウェイ |
| app コンテナ | `10.10.10.101` | Next.js アプリ (6サイト) |
| db コンテナ | `10.10.10.102` | PostgreSQL + Redis |
| game コンテナ | `10.10.10.103` | cod-web |

## 通信の流れ

### 外部 → サイトへのアクセス

```
ユーザー (ブラウザ)
    │
    ▼
shiratama.mydns.jp (MyDNS.jp DDNS)
    │
    ▼
TP-Link ルーター (WAN側グローバルIP)
    │ ポート転送: 80,443 → 192.168.x.100 (nginx)
    ▼
nginx コンテナ (vmbr0: 192.168.x.100)
    │ SSL終端 + URLパスでルーティング
    │
    ├─→ /           → 10.10.10.101:3000 (Portfolio)
    ├─→ /dropmod/   → 10.10.10.101:3001 (DropMod)
    ├─→ /flashcard/ → 10.10.10.101:3002 (Flashcard)
    ├─→ /ytdl/      → 10.10.10.101:3003 (ytdl)
    ├─→ /admin/     → 10.10.10.101:3004 (Dashboard)
    ├─→ /palmide/   → 10.10.10.101:3005 (PalmIDE)
    └─→ /cod/       → 10.10.10.103:8080 (cod-web)
```

### 内部コンテナ間の通信

```
app (10.10.10.101)
    │
    ├─→ db (10.10.10.102:5432)  — PostgreSQL
    └─→ db (10.10.10.102:6379)  — Redis

game (10.10.10.103)
    │
    └─→ db (10.10.10.102:5432)  — PostgreSQL

nginx (192.168.x.100)
    │
    ├─→ app (10.10.10.101)      — プロキシ先
    └─→ game (10.10.10.103)     — プロキシ先
```

> **重要:** vmbr1 のコンテナ（app, db, game）からは **外部に直接アクセスできません**。
> nginx コンテナは **vmbr0 と vmbr1 の両方**に接続する必要があります。

## 設定手順（概要）

### 1. Proxmox VE でブリッジを作成

**vmbr0** (既存のブリッジ、物理NICに接続):
```
# /etc/network/interfaces の例
auto vmbr0
iface vmbr0 inet static
    address 192.168.x.2/24
    gateway 192.168.x.1
    bridge-ports enp1s0    # 物理NIC名（環境による）
    bridge-stp off
    bridge-fd 0
```

**vmbr1** (新規作成、内部専用):
```
auto vmbr1
iface vmbr1 inet static
    address 10.10.10.1/24
    bridge-ports none      # 物理NICに接続しない = 外部から隔離
    bridge-stp off
    bridge-fd 0
```

### 2. ルーターのポート転送設定

TP-Link の管理画面で以下を設定:

| 外部ポート | 内部IP | 内部ポート | プロトコル | 用途 |
|-----------|--------|-----------|----------|------|
| 80 | 192.168.x.100 | 80 | TCP | HTTP |
| 443 | 192.168.x.100 | 443 | TCP | HTTPS |

### 3. nginx コンテナのネットワーク設定

nginx は **vmbr0 と vmbr1 の両方**に接続する（2つのNICを持つ）:

- **eth0:** vmbr0 — `192.168.x.100/24` (外部からのアクセスを受ける)
- **eth1:** vmbr1 — `10.10.10.100/24` (内部コンテナにプロキシする)

### 4. その他のコンテナのネットワーク設定

| コンテナ | ブリッジ | IP | ゲートウェイ |
|---------|---------|-----|------------|
| app | vmbr1 | 10.10.10.101/24 | 10.10.10.1 |
| db | vmbr1 | 10.10.10.102/24 | 10.10.10.1 |
| game | vmbr1 | 10.10.10.103/24 | 10.10.10.1 |

## セキュリティのメリット

1. **外部から直接アクセスできるのは nginx だけ**
   - app, db, game のポートは外部に公開されない
   - 例: PostgreSQL (5432) や Redis (6379) が外部から直接アクセスされるリスクがゼロ

2. **内部コンテナは外部ネットに出られない**
   - db コンテナが侵害されても、外部への通信ができない
   - ※ app コンテナは外部API（Modrinth, YouTube等）へのアクセスが必要なため、**NAT 経由での外部通信を許可**する設定が必要

3. **nginx が唯一の窓口**
   - SSL終端、Fail2Ban、レートリミット等を1箇所で管理
